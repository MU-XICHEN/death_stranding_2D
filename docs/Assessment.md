### 2.2 核心游戏体验与流程（20 分）

*原文子模块：Game Controllable Hero, Camera & Menus。*

| 完成  | 评分要求                                                     |
| ----- | ------------------------------------------------------------ |
| - [ ] | 玩家能够控制一名英雄，英雄具有**可用武器与生命值（Health）**。 |
| - [ ] | **相机跟随英雄**移动。                                       |
| - [ ] | 提供**多个可选英雄**，每个英雄在外观、优势与弱点上存在区别。 |
| - [ ] | 单个游戏关卡能够运行**至少 2 分钟**。                        |
| - [ ] | 构建循环游戏流程：**开场（Intro）→ 菜单（Menu）→ 游戏（Gameplay）→ 结算（Tally）→ 再次进入流程**。 |
| - [ ] | 至少提供**两个使用不同地图的关卡**：一个**无限地图**，一个**固定边界地图**。 |

| - [ ] | 游戏运行期间**始终显示 FPS**。                               |

| - [ ] | 静态生成实体受到足够伤害后，**停止生成 NPC**。               |
| - [ ] | 各种英雄具有**独特的攻击选择与第二技能**。                   |
| - [ ] | 实现**近战攻击（Melee Attack）**。                           |
| - [ ] | 实现**投射物攻击（Projectile Attack）**。                    |

| - [ ] | 实现**增强防御技能（Stronger Defence Skill）**。             |

### 2.4 碰撞与网格系统（20 分）

*原文子模块：Static, Invisible and Trigger Entities supporting World and Interaction。*

| 完成  | 评分要求                                                     |
| ----- | ------------------------------------------------------------ |
| - [ ] | **NPC 接触英雄**时，NPC 能造成伤害。                         |
| - [ ] | 英雄发动攻击且**接触/命中实体**时，实体受到伤害。            |

| - [ ] | **英雄投射物命中实体**时，实体受到伤害。                     |
| - [ ] | 处理**移动实体发射的投射物与英雄**之间的碰撞/交互。          |

| - [ ] | 至少有 **2 种 Tile / 地形类型**，其中一种不可通行（如墙体）。 |
| - [ ] | 实现**数据驱动的地图加载**：从**自定义文件格式**读取 Tile 与地图数据。 |

### 2.6 游戏实现的隐性评分重点

以下不是新增加的独立给分项，而是**原文明确表示会影响评分质量**的实现原则（第 2、5 页）：

- 评估系统的**运行速度与效率**，尤其是实体数量增加后的表现。
- 为关键功能选择合适的**数据结构和算法**，并在报告中讨论其 **Big-O 时间/空间复杂度**。
- 保持良好的**软件设计、架构和代码可读性**。
- 特别考虑**大量实体 / 实体集合**的组织与更新效率。
- 即使部分功能未完成，也提交已完成的实现、解释尝试过程，并清楚说明完成范围。
- 用报告中的描述和**游戏截图**佐证关键系统的实现（例如碰撞系统）。

## 4. 开发与学术规范：务必遵守

| 完成  | 规则                                                         |
| ----- | ------------------------------------------------------------ |
| - [ ] | 使用**课程提供的 GamesEngineeringBase 框架**，用 **C++** 编写程序。 |
| - [ ] | **禁止使用 STL 数据结构**，例如 `std::vector`、`std::list`、`std::map`。 |
| - [ ] | **禁止使用外部 API**。                                       |
| - [ ] | 可使用或扩展**课堂上开发的代码、导师提供的解决方案**。       |
| - [ ] | **禁止从互联网、在线资源或其他同学处复制代码**。             |
| - [ ] | **禁止用 AI 生成代码**；作业指定的 AI 使用等级只有 **AI PLANNING（规划、构思、研究）**。 |
| - [ ] | 若在允许范围内借助 AI 进行思考/规划，应由自己开发、完善最终作品；遵守课程的 AI 声明要求。 |
| - [ ] | 为代码添加必要的**注释**，保持清楚、可读。                   |
| - [ ] | 保留**草稿、笔记与研究记录**至学籍注册结束之后，以便按要求核查。 |

**AI 政策解释：**第 6 页勾选的是 **AI PLANNING**，不是 AI COLLABORATION 或 FULL AI。因此仅可借助 AI 进行前期规划、创意发展和研究；不得将 AI 生成的程序代码作为本作业的代码提交。第 7 页明确警告，未经授权或未披露的 AI 使用可能构成学术不端。
